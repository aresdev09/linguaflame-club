# LinguaFlame Club

Групповой Telegram-бот для изучения английского с ИИ: слова и грамматика дня,
мини-игры, рейтинг группы и общий огонёк. Бот добавляется в учебную группу или
клуб, настройки задаёт администратор, участники соревнуются и учатся вместе.

## Что умеет

Команды в группе:

| команда | кто | что делает |
|---|---|---|
| `/start`, `/help` | все | короткая справка и список команд по ролям |
| `/setup`, `/settings` | админ | настройка группы: уровень, языки, часовой пояс, время поста, что публиковать, тихие часы |
| `/quiz [n]` | все | групповой квиз (по умолчанию 5 вопросов, максимум 10) |
| `/games` | все | меню мини-игр |
| `/scramble` | все | «Собери слово» (ответ — reply на сообщение раунда) |
| `/gap` | все | «Пропущенное слово» |
| `/race` | все | гонка переводов (быстрее ответ — больше очков) |
| `/truefalse` | все | «Правда или ложь» |
| `/word`, `/grammar` | все | слова и грамматика дня сейчас |
| `/top` | все | рейтинг группы: за неделю и за всё время |
| `/me` | все | личная статистика участника |
| `/streak` | все | огонёк группы: текущая серия, рекорд, активность сегодня |
| `/stop` | админ | остановить текущую игру |
| `/reset_scores` | админ | сбросить рейтинг группы (с откатом в течение 24 часов) |
| `/privacy` | все | что хранит бот; можно скрыться из рейтинга |

В личном чате бот объясняет, как добавить его в группу (кнопка «Add to group»),
и показывает `/help`. Команды игр и админов в личке отвечают понятным отказом,
а не молчат.

Автоматически (по локальному времени группы): пост дня со словами и грамматикой,
вечернее напоминание об огоньке, утреннее сообщение о потерянном огоньке, вехи
огонька (3, 7, 14, 30 и 100 дней) и итоги недели по понедельникам.

Ключевые правила работы:

- в группе одновременно идёт только одна игра; состояние игры принадлежит чату,
  а не человеку, поэтому перезапуск бота не теряет рейтинг и не оставляет
  «зависших» игр;
- один ответ участника на раунд, ответы после окончания времени не принимаются;
- команды управления доступны только администраторам группы; анонимные админы
  (служебный аккаунт `GroupAnonymousBot`) тоже считаются админами;
- включён privacy mode: бот видит команды и ответы на свои сообщения, поэтому
  текстовые ответы принимаются только как reply на сообщение раунда;
- всё исходящее идёт через очередь с лимитами Telegram (около 20 сообщений в
  минуту на чат и общий лимит в секунду), ошибки отправки не роняют бота;
- контент от ИИ кешируется и переиспользуется между группами одного уровня и
  языка, на каждый чат действует дневная квота запросов к ИИ;
- имена участников в ИИ не передаются: хранятся только id, username,
  отображаемое имя и очки; в сообщениях имена экранируются и показываются без
  `@`, чтобы бот не пинговал людей;
- все тексты бота — в локализации (по умолчанию `en`, дополнительно `ru`), язык
  интерфейса задаёт админ группы.

## Стек

Python 3.11+ (образ Docker — 3.12), aiogram 3 (async), PostgreSQL для
продакшена и SQLite для разработки, SQLAlchemy 2 async и Alembic, APScheduler, ИИ через
OpenAI-совместимый API (`AIClient`, ответы в JSON). Redis зарезервирован под
кеш и блокировки: адрес задаётся `REDIS_URL`, в текущей версии блокировки игр и
лимиты живут в базе и в памяти процесса.

## Быстрый старт (локально, SQLite)

```bash
# 1. Зависимости
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"   # Linux/macOS: .venv/bin/pip

# 2. Настройки: скопируйте .env.example в .env и заполните BOT_TOKEN, AI_API_KEY
copy .env.example .env

# 3. Схема базы (миграции Alembic)
.venv\Scripts\python -m alembic upgrade head

# 4. Бот
.venv\Scripts\python -m bot.main
```

По умолчанию используется SQLite (`DATABASE_URL=sqlite+aiosqlite:///...`). Для
PostgreSQL укажите в `.env` строку вида
`postgresql+asyncpg://user:password@localhost:5432/linguaflame_club` и повторите
`alembic upgrade head`.

### Запуск через Docker Compose

Compose поднимает бота, PostgreSQL и Redis и применяет миграции при старте:

```bash
copy .env.example .env       # Linux/macOS: cp .env.example .env
# заполните BOT_TOKEN и AI_API_KEY
docker compose up --build
```

Адреса базы и Redis для контейнеров задаёт сам `docker-compose.yml`
(`DATABASE_URL`, `REDIS_URL`), остальные настройки берутся из `.env`. Данные
PostgreSQL и Redis лежат в томах `pgdata` и `redisdata`.

### Необязательно: запасной банк вопросов

В репозитории есть файлы банка `data/question_bank/*.json` — запасной контент,
который используется, если ИИ не ответил. Загрузка идемпотентна и нужна один раз:

```bash
.venv\Scripts\python -m scripts.seed_question_bank --load
```

Перегенерировать банк своим ключом ИИ: `--generate`, затем `--load`.

## Переменные окружения

Полный список с комментариями — в `.env.example`. Самое важное:

| переменная | по умолчанию | что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен из @BotFather, обязателен |
| `BOT_USERNAME` | пусто | имя бота без `@` для ссылки «Add to group» |
| `DATABASE_URL` | SQLite-файл | адрес базы: SQLite или PostgreSQL |
| `REDIS_URL` | `redis://localhost:6379/0` | адрес Redis |
| `AI_SERVER_URL` | NVIDIA NIM | база OpenAI-совместимого API |
| `AI_API_KEY` | пусто | ключ ИИ |
| `AI_MODEL`, `AI_MODEL_FALLBACK` | — | основная и резервная модель |
| `AI_QUOTA_PER_DAY` | 30 | дневная квота запросов к ИИ на чат (0 — без лимита) |
| `AI_GLOBAL_DAILY_LIMIT` | 300 | общий дневной бюджет запросов к ИИ |
| `LOG_LEVEL` | INFO | уровень логирования |
| `LOG_JSON` | false | структурные логи одной JSON-строкой на событие |

Лимиты (`LIMIT_*`), очки (`SCORE_*`), время раундов (`*_ROUND_SECONDS`) и
настройки уборки данных (`MAINTENANCE_*`) настраиваются там же и не требуют
правки кода.

Планировщик:

| переменная | по умолчанию | что делает |
|---|---|---|
| `SCHEDULER_TICK_SECONDS` | 60 | как часто проверять чаты |
| `SCHEDULER_TIME_OFFSET` | 0 | сдвиг «сейчас» для ручной проверки |
| `SCHEDULER_REMINDER_TIME` | 20:00 | вечернее напоминание об огоньке |
| `SCHEDULER_STREAK_LOST_TIME` | 09:00 | утреннее сообщение о потере огонька |
| `SCHEDULER_JITTER_MAX_SECONDS` | 120 | разброс автосообщений между группами |
| `SCHEDULER_MESSAGES_PER_DAY` | 2 | предел автосообщений на чат в сутки |
| `SCHEDULER_DORMANT_DAYS` | 7 | через сколько дней без очков замолчать |
| `SCHEDULER_CONTENT_ATTEMPTS` | 3 | попытки собрать контент поста дня |
| `SCHEDULER_RETRY_DELAY_SECONDS` | 600 | пауза между попытками |

## Ручная проверка планировщика

Планировщик раз в минуту смотрит на часы и решает, что кому отправить: пост
дня, напоминание об огоньке, итоги недели. Чтобы не ждать нужного времени
суток, «сейчас» планировщика можно сдвинуть переменной
`SCHEDULER_TIME_OFFSET` — она не меняет часовой пояс группы и не трогает
настройки чатов, только точку зрения планировщика на текущее время.

```dotenv
# Планировщик считает, что сейчас на 3 часа позже
SCHEDULER_TIME_OFFSET=3h
# Уехать на сутки и 2 часа вперёд
SCHEDULER_TIME_OFFSET=1d2h
# Вернуться на 30 минут назад
SCHEDULER_TIME_OFFSET=-30m
# Число без единицы — минуты: это 90 минут вперёд
SCHEDULER_TIME_OFFSET=90
```

Поддерживаются дни (`d`), часы (`h`) и минуты (`m`), знак `-` сдвигает время
назад, `0` — обычный режим. Некорректное значение останавливает запуск с
понятной ошибкой.

Порядок проверки:

1. Поставьте `SCHEDULER_TICK_SECONDS=10`, чтобы не ждать минуту.
2. Установите время поста в группе (`/setup`) на ближайшее будущее или
   сдвиньте часы планировщика так, чтобы это время уже наступило.
3. Смотрите лог: `Чат <id>: отправляю пост дня (words)`. Повторный `tick`
   дубль не создаёт: в журнале уже есть запись за этот день.
4. Чтобы повторить проверку, удалите записи журнала и поста за нужный день
   (дата в журнале — локальная дата группы):
   ```sql
   DELETE FROM scheduled_messages WHERE chat_id = <id> AND date = (SELECT MAX(date) FROM scheduled_messages WHERE chat_id = <id>);
   DELETE FROM daily_posts WHERE chat_id = <id> AND date = (SELECT MAX(date) FROM daily_posts WHERE chat_id = <id>);
   ```
5. Верните `SCHEDULER_TIME_OFFSET=0` и обычный `SCHEDULER_TICK_SECONDS`.

Сдвиг действует только на автосообщения: игры, команды и `/word` работают по
настоящему времени. Сдвиг через полночь переносит и дату в журнале: пост за
«завтра» может уйти сегодня, а на следующий день его не будет. Это ожидаемо —
после проверки сразу верните `SCHEDULER_TIME_OFFSET=0`.

## Структура проекта

```
bot/
  main.py            # точка входа, сборка диспетчера и сервисов
  config.py          # настройки из окружения и .env
  database.py        # async-движок и фабрика сессий
  keyboards.py       # inline-клавиатуры
  sender.py          # очередь отправки с лимитами Telegram
  logging_setup.py   # текстовые и структурные (JSON) логи
  routers/           # обработчики aiogram: private, group_admin, quiz, games, daily, leaderboard, admin
  middlewares/       # контекст группы, кулдауны, перехват ошибок
  services/          # бизнес-логика без aiogram: games/, scoring, content, scheduler, streak, daily, maintenance
  repositories/      # доступ к базе
  prompts/           # промпты для ИИ
  locales/           # тексты интерфейса (en, ru)
migrations/          # Alembic
scripts/             # seed_question_bank.py
tests/               # pytest
data/question_bank/  # запасной банк вопросов
docs/                # инструкции по деплою и ручным проверкам
```
